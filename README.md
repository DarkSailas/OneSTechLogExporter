# 1С: Просмотр логов ТЖ и ЖР (OneSTechLogExporter)

Утилита и фоновая служба для быстрого анализа, фильтрации и выгрузки **Технологического Журнала (ТЖ)** и **Журнала Регистрации (ЖР)** 1С:Предприятие 8.3.

Умеет работать как настольный инструмент для расследования инцидентов (с таблицами, фильтрами и выгрузкой в Excel), так и как фоновая служба Windows для постоянной отправки логов в **Elasticsearch / OpenSearch** и локальные JSON-файлы.

---

## 🎯 Какие задачи решает

1. **Быстрый разбор тяжелых логов ТЖ и ЖР без зависаний:**
   Когда ТЖ разрастается на десятки гигабайт, текстовые редакторы и стандартные утилиты перестают открывать файлы или намертво виснут. Здесь парсинг потоковый (на `Span<char>` без лишних аллокаций), а таблица в GUI использует виртуализацию — сотни тысяч строк листаются плавно и без задержек.

2. **Расследование проблем «здесь и сейчас» (GUI):**
   Нужно быстро найти, кто запустил тяжелый запрос, какие фоновые задания подвесили базу, где возник `TLOCK` / `TDEADLOCK` или какие ошибки сыпались в Журнал Регистрации.

3. **Фоновый экспорт в Elasticsearch / OpenSearch 24/7 (Служба):**
   Служба висит в фоне, инкрементально считывает новые записи логов (с точностью до байта) и отправляет их пачками в Elastic для дашбордов Kibana. Файлы 1С читаются без блокировки (`FileShare.ReadWrite`), так что рабочим процессам `rphost` служба не мешает.

4. **Выгрузка отчетов в Excel и JSON:**
   Любую отфильтрованную выборку можно в один клик выгрузить в аккуратный `.xlsx` с автошириной колонок и цветовой подсветкой событий/ошибок или сохранить в формате JSON Lines (NDJSON).

## 🖥️ Возможности графического интерфейса (GUI)

* **Два независимых раздела:**
  * **Технологический журнал:** точное время, длительность в мс/мкс, событие (`DBMSSQL`, `EXCP`, `TLOCK`, `CALL`, `SCALL`, `SDBL` и др.), имя процесса, PID, SPID, поток OS, контекст 1С, SQL-запрос, параметры блокировок.
  * **Журнал регистрации:** дата, человекочитаемое событие («Сеанс. Начало», «Данные. Изменение»), пользователь, метаданные, статус транзакции (`Commit`, `Rollback`), важность (`Error`, `Warning`, `Information`), комментарий, номер сеанса.
* **Умный отбор по полям («ДА» и «НЕ»):**
  * В меню «ОТБОР ПО ПОЛЯМ» автоматически собираются все уникальные значения из текущей выборки с точным количеством записей.
  * Для каждого значения предусмотрены две симметричные кнопки: **`[ ДА ]`** (оставить в таблице только его) и **`[ НЕ ]`** (скрыть его из таблицы).
  * Можно гибко комбинировать: например, выбрать конкретного пользователя через `[ ДА ]`, но исключить фоновые задания `##AdminProcess##` через `[ НЕ ]`.
  * Предусмотрены быстрые кнопки `+ ВСЕ`, `НЕ ВСЕ`, `СНЯТЬ`.
* **Поиск с поддержкой исключений:**
  * Обычный поиск ищет совпадения по всем колонкам.
  * Если перед словом поставить `!` или `-` (например, `!Администратор`, `-ВнешнееСоединение`, `NOT:Фоновое`), эти строки будут исключены из просмотра.
* **Компактная панель активных фильтров:**
  * Все примененные фильтры выводятся в одну аккуратную строку над таблицей и не сдвигают сетку данных.
  * Если фильтров много, они автоматически сворачиваются в кнопку **`+N ещё фильтров ▼`**, по клику на которую открывается выпадающий список со всеми активными фильтрами и возможностью точечного удаления.
  * Есть быстрая кнопка **`СБРОСИТЬ ВСЕ`** для снятия всех активных фильтров за один клик.
* **Экспорт данных:**
  * Кнопка **«В EXCEL»** — формирует чистую таблицу `.xlsx` с автошириной колонок.
  * Кнопка **«В JSON»** — сохраняет выборку в файл JSON Lines.
  * Кнопка **«В ELASTIC»** — отправляет выбранные строки в настроенный кластер Elasticsearch / OpenSearch.

## ⚙️ Как устроена фоновая служба (Windows Service)

* **Инкрементальное чтение (Byte-Offset):**
  Служба сохраняет позицию чтения каждого файла в `state.json`. При следующем опросе читаются только новые строки, без перечитывания файлов с начала и без дублирования записей.
* **Потоковая обработка:**
  Чтение идет через буфер 128 КБ с поиском границ записей. Потребление оперативной памяти остается в районе 30–50 МБ даже на терабайтных объемах логов.
* **Локальные дампы (JSON Lines):**
  Если Elastic временно недоступен или не используется, служба может складывать распарсенные данные в каталог `parsed_logs/` с авторотацией по размеру (например, до 50 МБ на файл) и количеству файлов.
* **Отправка в Elasticsearch:**
  Отправка идет пачками через Bulk API (`BulkBatchSize: 1000`). Имена служебных полей (вроде `p:processName` или `t:computerName`) автоматически приводятся к безопасному виду без двоеточий, чтобы не ломать маппинги Elastic.

## 🚀 Быстрый старт

### Вариант 1. Запуск GUI-приложения
Просто запустите:
```text
publish\Gui\OneSTechLogExporter.Gui.exe
```
Установка .NET Runtime не требуется — приложение собрано в автономном режиме (Self-Contained x64).

### Вариант 2. Установка фоновой службы Windows

1. Откройте файл `publish\Service\appsettings.json` и укажите ваши пути к логам и параметры подключения:
   ```jsonc
   {
     "Exporter": {
       "PollingIntervalSeconds": 60,
       "EventLog": {
         "Enabled": true,
         "DirectoryPath": "C:/Logs/LGLogs"
       },
       "TechLog": {
         "Enabled": true,
         "DirectoryPath": "C:/Logs/TGLogs"
       },
       "Elastic": {
         "Enabled": true,
         "ServerUrl": "http://localhost:9200",
         "Username": "",
         "Password": ""
       }
     }
   }
   ```
2. Запустите PowerShell от имени Администратора и выполните скрипт установки:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\publish\Service\INSTALL_SERVICE.ps1
   ```
   Скрипт зарегистрирует службу **OneSTechLogExporter** с автозапуском при старте Windows и автоматическим перезапуском при сбоях.

3. Для управления службой используйте стандартные команды или скрипты:
   * **Обновление службы:** `powershell -ExecutionPolicy Bypass -File .\publish\Service\UPDATE_SERVICE.ps1`
   * **Удаление службы:** `powershell -ExecutionPolicy Bypass -File .\publish\Service\UNINSTALL_SERVICE.ps1`

## 🛠️ Сборка из исходников (для разработчиков)

Для сборки проекта потребуется **.NET 10.0 SDK**.

В корне проекта выполните:
```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт:
1. Остановит запущенные процессы службы и GUI.
2. Восстановит зависимости NuGet.
3. Соберет проект в конфигурации `Release`.
4. Запустит автоматические Unit-тесты.
5. Опубликует готовые автономные сборки в папки `./publish/Service` и `./publish/Gui`.
