# 1С: Просмотр логов ТЖ и ЖР (OneSTechLogExporter) v1.4.0

Высокопроизводительная утилита и фоновая служба Windows на **.NET 10 / C# 14** для быстрого анализа, фильтрации и выгрузки **Технологического Журнала (ТЖ)** и **Журнала Регистрации (ЖР)** 1С:Предприятие 8.3/8.2 в текстовом формате (`*.lgp`, `1Cv8.lgf`, `*.lgx`) и формате базы SQLite (`1Cv8.lgd`).

Умеет работать как настольный инструмент для расследования инцидентов (с аппаратной виртуализацией таблиц, динамическими фильтрами, гибридным дисковым кэшем сессии, неблокирующим UI и выгрузкой в Excel), так и как отказоустойчивая служба Windows для постоянной инкрементальной отправки логов в **Elasticsearch / OpenSearch** и локальные JSON-файлы.

---

## 🎯 Ключевые возможности и архитектурные решения (v1.4.0)

### 1. Мгновенный разбор тяжелых логов без зависаний (100+ ГБ)
Когда журналы 1С разрастаются на десятки и сотни гигабайт, текстовые редакторы и стандартные инструменты платформы зависают либо аварийно завершаются по нехватке памяти (`OutOfMemoryException`). В OneSTechLogExporter реализован многоуровневый комплекс оптимизаций:
* **Быстрый бинарный поиск даты ($O(\log N)$ Fast Seek):** при отборе по датам в недельных/месячных логах `.lgp` утилита не читает десятки гигабайт предшествующих дней построчно, а за ~25 точечных seek-запросов (< 150 мс) находит точное байтовое смещение начала целевого диапазона. Сетевой трафик SMB/NAS сокращается с 50–100 ГБ до ~500 МБ, ускоряя выборку в 50–100 раз. В строке состояния отображается точный объем пропущенных байтов (например, `Бинарный поиск даты: пропущено 48.3 ГБ`).
* **Гибридный дисковый кэш сессии (SQLite WAL Session Cache):** распарсенные события в реальном времени сохраняются в легковесную локальную базу SQLite в режиме WAL (`session_*.db` в каталоге `%TEMP%\OneSTechLogExporter`). Это разгружает оперативную память процесса, позволяет мгновенно фильтровать и переключать выборки без повторного чтения с диска или сети.
* **Индикатор размера дискового кэша (`💾 TEMP: XX.X МБ`):** в правой части статус-бара выводится актуальный размер файла сессионного кэша на диске. По клику на бейдж Проводник Windows автоматически открывает папку с временными файлами программы. При закрытии приложения или старте нового разбора кэш сессии автоматически очищается.
* **Неблокирующий конвейер обработки (Zero-Freeze Concurrency Pipeline):** чтение файлов (Producer) и запись в локальный кэш с обновлением UI (Consumer) разделены через асинхронный канал `System.Threading.Channels.Channel<T>` в пуле потоков `Task.Run`. Прогресс парсинга рассчитывается непрерывно по байтам с троттлингом таймера в 80 мс на фоновом приоритете `DispatcherPriority.Background`. Интерфейс приложения сохраняет плавные 60 FPS, а кнопка **«ОТМЕНА»** реагирует мгновенно.
* **Pushdown-фильтрация дат для SQLite (`.lgd`):** фильтры периода транслируются напрямую в параметры SQL-запроса (`WHERE date >= @minDateVal AND date <= @maxDateVal`), исключая считывание нерелевантных записей из базы.
* **Zero-Allocation парсинг:** чтение словаря `1Cv8.lgf` и записей логов выполнено на чистых срезах памяти `ReadOnlySpan<char>` / `ReadOnlySpan<byte>` без регулярных выражений и аллокаций мусорных строк.

### 2. Поддержка всех форматов Журнала Регистрации 1С
* Текстовый формат 1С 8.2 / 8.3 (`*.lgp`, `1Cv8.lgf`).
* Индексные файлы событий (`*.lgx`) с автоматическим поиском парного файла данных.
* SQLite формат нового журнала 1С 8.3 (`1Cv8.lgd`) с неблокирующим чтением в режиме `Mode=ReadOnly; Cache=Shared`.

---

### 3. Глубокая детализация событий Журнала Регистрации
Извлекаются и декодируются все атрибуты формата 1С:
* **Компьютер / Рабочая станция (`Computer`):** сетевое имя ПК или терминального сервера.
* **Рабочий сервер 1С (`Server`):** имя ноды кластера серверов 1С, выполнившей действие.
* **Номер соединения (`Connection`):** TCP-соединение в кластере 1С для сквозной корреляции с ТЖ.
* **Порт процесса (`Port`):** IP-порт рабочего процесса `rphost`.
* **Представление данных (`DataPresentation`):** наглядное строковое имя объекта (документа, справочника, регистра).
* **Статус транзакции (`TranStatusText`):** расшифровка `Зафиксирована`, `Отменена`, `В процессе`, `Вне транзакции`.
* **Тип клиента (`AppTypeName`):** понятное имя (`Тонкий клиент`, `Толстый клиент`, `Фоновое задание`, `Веб-клиент`, `Web-сервис`, `HTTP-сервис`, `Конфигуратор`).
* Дата, пользователь, метаданные, комментарий, важность, сеанс, имя файла и его размер.

---

### 4. Расследование проблем «здесь и сейчас» (GUI)
Быстрый поиск тяжелых запросов к СУБД, зависших фоновых заданий, взаимных блокировок (`TLOCK`, `TDEADLOCK`), утечек памяти или критических ошибок в Журнале Регистрации.

---

### 5. Фоновый экспорт в Elasticsearch / OpenSearch 24/7 (Служба)
Служба работает в фоне, инкрементально считывает новые записи логов (с точностью до байта через `StateTracker`) и отправляет их пачками в Elastic для дашбордов Kibana. Файлы 1С читаются без блокировки (`FileShare.ReadWrite`), не мешая рабочим процессам `rphost`.

---

### 6. Выгрузка отчетов в Excel и JSON
Любую отфильтрованную выборку можно в один клик выгрузить в аккуратный `.xlsx` с автошириной колонок и форматированием или сохранить в формате JSON Lines (NDJSON).

## 🖥️ Возможности графического интерфейса (GUI v1.4.0)

* **Стартовый экран по умолчанию:**
  * При запуске приложения всегда автоматически открывается вкладка **«Технологический журнал (ТЖ)»** с лимитом **«Все записи»**.
* **Единая кнопка выбора источников «ОБЗОР ▾»:**
  * Выпадающее меню с выбором: **«📁 Выбрать каталог (папку)...»** или **«📄 Выбрать файл...»**.
  * Поддержка Drag & Drop папок и отдельных файлов (`.log`, `.lgp`, `.lgd`, `.lgx`, `1Cv8.lgf`).
  * Автономный разбор: программа успешно парсит лог, даже если указан один отдельный файл без окружающей структуры каталогов 1С.
* **Два независимых раздела анализа:**
  * **Технологический журнал:** точное время, длительность в мс/мкс, событие (`DBMSSQL`, `EXCP`, `TLOCK`, `CALL`, `SCALL`, `SDBL` и др.), имя процесса, PID, SPID, поток OS, контекст 1С, SQL-запрос, параметры блокировок.
  * **Журнал регистрации:** дата и время, событие («Сеанс. Начало», «Данные. Изменение»), важность (`Ошибка`, `Предупреждение`, `Информация`), пользователь, компьютер, приложение, тип клиента, метаданные, представление данных, сервер, порт, сеанс, соединение, статус транзакции, имя файла источника, размер файла, комментарий.
* **Построчное и групповое удаление строк из таблицы:**
  * Возможность точечно или массово удалять выбранные события из таблицы ЖР для исключения шума при анализе.
  * Удаление доступно по клавише <kbd>Delete</kbd>, кнопке **«УДАЛИТЬ»** в панели инструментов и через контекстное меню (ПКМ).
  * Диалоговое окно с подтверждением операции и указанием числа удаляемых строк.
* **Адаптивная верстка панели фильтров:**
  * Кнопки действий (`УДАЛИТЬ`, `ОЧИСТИТЬ`) и бейдж счётчика записей сгруппированы у правого края с эластичным разделителем — счётчик записей всегда полностью виден и не обрезается при любом разрешении и DPI-масштабировании экрана.
* **Умный отбор по полям («ДА» и «НЕ»):**
  * В меню «ОТБОР ПО ПОЛЯМ» автоматически собираются все уникальные значения из текущей выборки с точным количеством записей.
  * Для каждого значения предусмотрены две кнопки: **`[ ДА ]`** (оставить только его) и **`[ НЕ ]`** (исключить его).
  * Быстрые кнопки `+ ВСЕ`, `НЕ ВСЕ`, `СНЯТЬ`.
* **Полнотекстовый поиск с префиксами и отрицаниями:**
  * Поиск ищет совпадения по всем колонкам.
  * Поддержка префиксов полей: `user:`, `comp:`, `server:`, `event:`, `app:`, `meta:`, `data:`, `session:`, `file:`, `comment:`.
  * Знак `!` или `-` перед словом (например, `!Администратор`, `-ВнешнееСоединение`, `NOT:Фоновое`) исключает соответствующие строки из просмотра.
* **Компактная панель активных фильтров:**
  * Все примененные фильтры выводятся в виде интерактивных чипов над таблицей.
  * При большом числе фильтров они сворачиваются в кнопку **`АКТИВНЫЕ ФИЛЬТРЫ (N) ▼`** с возможностью точечного сброса или кнопки **`СБРОСИТЬ ВСЕ`**.
* **Интерактивный календарь и фильтрация по периоду дат:**
  * **Выбор одного дня в 1 клик:** клик по любой дате сразу фиксирует этот конкретный день (`С = ПО = выбранная дата`).
  * **Интуитивный выбор интервала в 2 клика:** клик по второй дате автоматически формирует диапазон дат.
  * Готовые пресеты в один клик: **«Сегодня»**, **«Вчера»**, **«3 дня»**, **«7 дней»**, **«30 дней»**, **«Этот месяц»**, **«Все логи»**.
* **Экспорт и импорт профилей фильтрации (JSON):**
  * Сохранение всех настроенных фильтров, путей и параметров в переносимый JSON-файл для быстрого обмена сценариями расследования между инженерами.
* **Мониторинг ресурсов и сброс оперативной памяти:**
  * Бейдж версии и даты сборки в статус-баре (`v1.4.0 • 04.09.2026`).
  * Бейдж дискового кэша (`💾 TEMP: XX.X МБ`) с прямым открытием папки кэша по клику.
  * Кнопка **«СБРОС RAM»** для принудительного вызова сборщика мусора .NET (`GC.Collect`) и немедленного освобождения неиспользуемой памяти.
* **Экспорт данных:**
  * **«EXCEL»** — формирование файла Microsoft Excel (`.xlsx`) с автошириной колонок и табличными стилями.
  * **«JSON»** — сохранение выборки в формат JSON Lines.
  * **«В ELASTIC»** — прямая потоковая отправка отображаемых записей в настроенный индекс Elasticsearch / OpenSearch.

## ⚙️ Архитектура фоновой службы (Windows Service)

* **Инкрементальное чтение (Byte-Offset Tracking):**
  Служба сохраняет позицию чтения каждого файла в `state.json`. При очередном цикле опроса читаются только новые байты, без повторного чтения файлов с начала и без дублей.
* **Потоковая обработка с минимальным оверхедом:**
  Чтение идет через кольцевой буфер с поиском границ записей. Потребление памяти стабильно держится в районе 30–50 МБ даже на терабайтных логах.
* **Локальные дампы (JSON Lines):**
  Возможность записи распарсенных данных в локальную директорию дампа с авторотацией по размеру файлов.
* **Пакетная выгрузка в Elasticsearch:**
  Отправка пачками через Bulk API (`BulkBatchSize: 1000`). Имена полей приводятся к каноническому виду без служебных спецсимволов.

## 🚀 Быстрый старт

### Вариант 1. Запуск GUI-клиента
Запустите:
```text
publish\Gui\OneSTechLogExporter.Gui.exe
```
Приложение собрано под `win-x64` и готово к работе без предварительной настройки.

### Вариант 2. Установка фоновой службы Windows

1. В файле `publish\Service\appsettings.json` укажите пути к каталогам логов и параметры Elasticsearch:
```jsonc
{
  "Exporter": {
    "PollingIntervalSeconds": 60,
    "EventLog": {
      "Enabled": true,
      "DirectoryPath": "C:/Logs/1C/reg_1541"
    },
    "TechLog": {
      "Enabled": true,
      "DirectoryPath": "C:/Logs/1C/techlog"
    },
    "Elastic": {
      "Enabled": true,
      "ServerUrl": "http://localhost:9200",
      "Username": "",
      "Password": ""
    }
  }
}
```

2. Запустите PowerShell от имени Администратора и выполните скрипт установки:
```powershell
powershell -ExecutionPolicy Bypass -File .\publish\Service\INSTALL_SERVICE.ps1
```
Служба **OneSTechLogExporter** будет установлена с типом запуска «Автоматически» и автоперезапуском при сбоях.

3. Скрипты управления службой:
* **Обновление бинарников:** `powershell -ExecutionPolicy Bypass -File .\publish\Service\UPDATE_SERVICE.ps1`
* **Удаление службы:** `powershell -ExecutionPolicy Bypass -File .\publish\Service\UNINSTALL_SERVICE.ps1`

## 🛠️ Сборка и публикация

Для сборки проекта требуется **.NET 10.0 SDK**.

В корне проекта выполните:
```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт автоматически:
1. Останавливает активные процессы приложения и службы.
2. Восстанавливает зависимости (`dotnet restore`).
3. Собирает проект в конфигурации `Release`.
4. Запускает автоматические Unit-тесты.
5. Публикует оптимизированные сборки в `./publish/Service` и `./publish/Gui`.
6. Синхронизирует артефакты сборки и исходные коды.
